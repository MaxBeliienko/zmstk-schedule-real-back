# ZMSTK Schedule — бекенд

REST API системи розкладу автошколи ЗМСТК: реальний графік інструкторів, плановий графік занять, база курсантів з оплатами, транспортні засоби (МТБ), інструктори, календар нагадувань та документ «Графік черговості навчання водінню» (Word).

Фронтенд — окремий репозиторій `zmstk-schedule-real-front`.

## Стек

- Node.js ≥ 20, Express 4
- MongoDB + Mongoose 8
- JWT (`jsonwebtoken`); паролі — scrypt з секретним «перцем» (`utils/passwords.js`)
- `helmet`, `cors`
- `swagger-ui-express`: документація API на `/api/docs`
- `docx`: генерація графіка групи у Word

## Швидкий старт

```bash
npm install
cp .env.example .env      # заповніть змінні (див. нижче)
npm run dev               # node --watch, перезапуск при змінах
# або
npm start                 # звичайний запуск
```

Сервер стартує на `http://localhost:8080` (або `PORT`). Перевірка: `GET /health`.

Під час старту сервер:
1. перевіряє `JWT_SECRET` і `PASSWORD_PEPPER`: без них (або якщо вони коротші за 16 символів) сервер не запускається;
2. підключається до MongoDB (`MONGODB_URI`);
3. перевіряє, що `PASSWORD_PEPPER` той самий, з яким створено паролі в цій базі (інакше зупиняється з поясненням);
4. виконує одноразові міграції даних з `migrations/index.js`. Кожна міграція виконується рівно один раз, журнал зберігається в колекції `migrations`;
5. якщо в базі немає жодного активного адміністратора, створює його з паролем `ADMIN_PASSWORD`.

## Змінні середовища

| Змінна | Обов'язкова | Опис |
|---|---|---|
| `PORT` | ні | Порт HTTP-сервера, за замовчуванням `8080` |
| `MONGODB_URI` | так | Рядок підключення до MongoDB |
| `JWT_SECRET` | так | Секрет підпису токенів, мінімум 16 символів |
| `PASSWORD_PEPPER` | так | Секрет для хешування паролів, мінімум 16 символів. **Не змінюйте і не втрачайте** — див. «Паролі та PASSWORD_PEPPER» |
| `PASSWORD_PEPPER_OLD` | ні | Попередній `PASSWORD_PEPPER` — лише на час його заміни |
| `ADMIN_PASSWORD` | для першого запуску | Пароль першого адміністратора: коли в базі ще немає жодного адміна, і для аварійного відновлення (`npm run reset-admin`) |
| `ACCOUNTANT_PASSWORD` | ні | Пароль першого бухгалтера: лише одноразово при переході на облікові записи |
| `CORS_ORIGIN` | рекомендовано | Дозволені домени фронтенду через кому. Якщо не задано, API приймає запити з будь-якого домену |
| `TRUST_PROXY` | за проксі | Кількість проксі перед сервером: `0` — без проксі, `1` — Render / Railway / Cloud Run. Від цього залежить правильна IP-адреса клієнта для лімітів входу |
| `DOC_APPROVER_POSITION`, `DOC_APPROVER_ORGANIZATION`, `DOC_APPROVER_NAME` | ні | Шапка «ЗАТВЕРДЖУЮ» у Word-графіку групи (за замовчуванням значення з `config/documents.js`) |
| `NODE_ENV` | ні | `production` додатково захищає seed-скрипти від запуску |

Після першого запуску паролі адміністраторів і бухгалтерів змінюються в інтерфейсі (сторінка «Користувачі»), а не в `.env`.

> Перевірка `TRUST_PROXY`: `GET /health` повертає поле `ip`. Воно має збігатися з вашою реальною IP-адресою. Якщо там адреса проксі, збільште `TRUST_PROXY`.

## Початкові дані (seed)

Скрипти **видаляють** дані в базі з `MONGODB_URI` і заповнюють її заново, тому запускаються лише з явним підтвердженням:

```bash
node seedPlannedData.js --yes                 # інструктори, ТЗ і довідник вправ
node seed.js --yes                            # інструктори і ТЗ (без довідника вправ)
NODE_ENV=production node seed.js --yes --production   # бойова база — лише свідомо
```

Довідник вправ (колекція `exercisecategories`) потрібен для планового графіка: тривалість, автодром і час закінчення заняття беруться саме з нього.

> `seed.js` і `seedPlannedData.js` додані в `.gitignore`, тож на новій машині їх треба скопіювати вручну.

## Ролі та авторизація

Вхід один для всіх: користувач вводить **лише пароль** (`POST /api/auth/login`), а роль визначає знайдений обліковий запис (колекція `accounts`).

| Роль | Можливості |
|---|---|
| `instructor` | Власний реальний графік (редагування — від позавчора і далі), журнал своїх курсантів, календар |
| `admin` | Усе, включно з плановим графіком, видаленням курсантів та інструкторів, керуванням користувачами |
| `accountant` | Курсанти й оплати, МТБ, інструктори, календар (без видалення і без планового графіка) |

- **Облікові записи.** Адміністраторів і бухгалтерів додає адмін на сторінці «Користувачі» (`/api/accounts`): ім'я, роль, пароль, блокування. Пароль інструктора задається в розділі «Інструктори». В історії передплат видно, хто саме вніс зміну.
- **Паролі унікальні.** Двох однакових паролів бути не може: це гарантує унікальний індекс у БД. Нові паролі — щонайменше 8 символів (можна лише цифри). Старі 6-значні PIN інструкторів діють, доки їх не змінять.
- Токен передається в заголовку `Authorization: Bearer <token>` і діє 30 днів. Зміна пароля, ролі, блокування чи видалення облікового запису одразу завершує всі його сесії.
- **Захист від підбору:** після 10 невдалих спроб з однієї IP вхід з неї блокується на 15 хв. Лічильник зберігається в БД (колекція `loginattempts`), тож спільний для всіх інстансів сервера.
- Вхідні дані очищаються від NoSQL-операторів (`middlewares/sanitize.js`).

### Паролі та PASSWORD_PEPPER

Логіна немає, тож обліковий запис шукається за самим паролем. Тому пароль хешується детерміновано: scrypt із секретним «перцем» `PASSWORD_PEPPER`. Без цього секрету викрадена база не дає підібрати паролі.

- **Збережіть `PASSWORD_PEPPER` у надійному місці.** Якщо його змінити або втратити, жоден пароль не підійде.
- Якщо локальний `.env` під'єднаний до тієї самої бази, що й робочий сервер, значення мають збігатися до символу. Сервер з іншим перцем не стартує й пояснює чому.
- **Планова заміна перцю** (наприклад, якщо секрет міг потрапити до сторонніх):
  1. новий секрет запишіть у `PASSWORD_PEPPER`, а попередній — у `PASSWORD_PEPPER_OLD`;
  2. перезапустіть сервер. Користувачі входять як завжди, і при вході їхній пароль автоматично переводиться на новий перець;
  3. коли всі хоча б раз увійдуть, приберіть `PASSWORD_PEPPER_OLD`.
- **Аварійне відновлення** (перець втрачено):
  1. задайте в `.env` новий `PASSWORD_PEPPER` і `ADMIN_PASSWORD` (новий пароль адміна);
  2. виконайте `npm run reset-admin -- --yes` з `MONGODB_URI` робочої бази;
  3. увійдіть адміном і задайте нові паролі іншим користувачам («Користувачі» та «Інструктори»).

## API (коротко)

Усі відповіді мають формат `{ success: true, ... }` або `{ success: false, message }`.

Повна інтерактивна документація — **Swagger UI на `/api/docs`** (локально: http://localhost:8080/api/docs). Натисніть **Authorize**, вставте токен — і запити можна виконувати просто зі сторінки. Опис маршрутів лежить у `docs/openapi.js`: додаючи чи змінюючи маршрут, оновіть і його.

| Метод і шлях | Ролі | Призначення |
|---|---|---|
| `GET /api/config` | — | Спільні налаштування для фронтенду (категорії, години, ліміти, варіанти нагадувань) |
| `POST /api/auth/login` | — | Вхід за паролем (роль визначається обліковим записом) |
| `GET /api/auth/me` | усі | Поточна сесія |
| `GET/POST /api/accounts`, `PUT/DELETE /api/accounts/:id` | admin | Облікові записи адміністраторів і бухгалтерів |
| `GET /api/instructors` | усі | Список ПІБ і категорій |
| `GET /api/instructors/staff` | admin, accountant | Інструктори зі строками медогляду / санкнижки |
| `POST /api/instructors`, `PUT /api/instructors/:id` | admin, accountant | Створення / редагування. `password` (при створенні обов'язковий) змінює пароль і завершує всі сесії інструктора |
| `DELETE /api/instructors/:id` | admin | Видалення (лише без майбутніх занять) |
| `GET /api/instructors/me/autodrome` | instructor | Заняття на автодромі з планового графіка |
| `GET /api/instructors/:id/students` | instructor (свій), admin | Журнал курсантів інструктора |
| `GET/POST/PUT /api/vehicles` | усі / admin, accountant | Транспортні засоби (МТБ) |
| `GET /api/schedule/instructor-day` | усі (інструктор — свій) | Реальний графік інструктора на день |
| `POST /api/schedule/save` | instructor (свій), admin | Збереження реального графіка дня |
| `GET /api/schedule/admin-day`, `/admin-instructor-period` | admin, accountant | Зведений день / графік за період |
| `GET /api/admin/students` | admin, accountant | Курсанти. Параметри: `search`, `includeArchive=true`, `endFrom` + `endTo` (дата закінчення навчання в періоді, для підрахунку випуску; архів тоді враховується завжди) |
| `POST/PUT /api/admin/students[/:id]` | admin, accountant | Створення / часткове оновлення (передаються лише змінені поля) |
| `DELETE /api/admin/students/:id` | admin | Видалення разом з його плановими заняттями |
| `GET /api/admin/students-summary` | admin | Курсанти «Практики» за період навчання |
| `GET /api/admin/students/:id/details` | admin, accountant | Статистика курсанта за вправами |
| `GET/POST/PUT/DELETE /api/admin/planned-schedule[/:id]` | admin | Плановий графік (перевірка конфліктів ТЗ / причепа / курсанта / інструктора). GET: `startDate`, `endDate` (обов'язкові), `instructorId` або `vehicleId` (заняття, де ТЗ — основне авто або причіп; для звіту по ТЗ) |
| `GET /api/admin/planned-schedule/available-resources` | admin | Вільні курсанти й ТЗ на інтервал |
| `GET /api/admin/exercises` | admin | Довідник вправ |
| `GET /api/admin/group-schedule/document?group=N` | admin | Word-графік групи |
| `/api/reminders/*` | усі | Календар: картки, повторення, спливаючі сповіщення |

## Тести

```bash
npm test             # усі тести (≈ 1 хв)
npm run test:unit    # лише логіка без БД (кілька секунд)
```

- `tests/unit/` — чиста логіка: дати за Києвом, статуси курсантів, повторення нагадувань, Word-графік групи.
- `tests/api/` — запити до API так, як їх робить фронтенд: вхід за паролем і ліміт спроб, облікові записи, зміна пароля, міграція і заміна перцю, конфлікти планового й реального графіка, звіт по ТЗ, оплати курсантів.
- API-тести запускають **тимчасову MongoDB у пам'яті** (`mongodb-memory-server-core`) у режимі replica set, як на Atlas, щоб працювали транзакції. Реальна база з `.env` не використовується. Під час першого запуску MongoDB завантажується (~100 МБ) і кешується.
- Запускайте тести перед кожним деплоєм: якщо щось зламалось, тест укаже, що саме.

## Word-графік групи

`utils/groupSchedule.js` готує дані (без форматування), а `utils/groupScheduleDocx.js` формує документ:
- формат А4, альбомна орієнтація, по 14 навчальних днів на таблицю;
- курсанти згруповані за основним авто;
- клітинки днів, у які курсант має заняття **на автодромі**, заливаються світло-зеленим (`AUTODROME_FILL`). Під таблицею є умовне позначення.

## Структура

```
app.js         Express-застосунок (маршрути, middleware) — без запуску
server.js      підключення до БД, міграції, запуск app
tests/         автотести (tests/unit — логіка, tests/api — API на тимчасовій БД)
config/        константи (категорії, слоти, JWT, паролі, реквізити документів)
docs/          опис API для Swagger (openapi.js)
middlewares/   авторизація, ролі, санітизація, обробка помилок
migrations/    одноразові міграції даних при старті
models/        Mongoose-моделі
routes/        маршрути API (routes/admin/* — під /api/admin)
utils/         дати (за Києвом), паролі й облікові записи, блокування, нагадування, Word-графік
scripts/       службові скрипти (аварійне відновлення адміна)
```

## Важливі принципи

- **Дати** — рядки `YYYY-MM-DD`, «сьогодні» рахується за Києвом (`utils/dates.js`), арифметика — через UTC.
- **Конфлікти бронювання** перевіряються під розподіленим блокуванням (`utils/keyedLock.js`, колекція `locks`), яке коректно працює і з кількома інстансами сервера. Унікальні індекси є останньою лінією захисту.
- **Спільні налаштування** (категорії, години графіків, ліміти, мінімальна довжина пароля, варіанти нагадувань) живуть лише на бекенді: `config/categories.js`, `config/timeSlots.js`, `config/passwords.js`, `utils/reminderOffsets.js`. Фронтенд отримує їх з `GET /api/config` під час старту, тож змінювати значення потрібно тільки тут.
- **Транзакції.** Операції, що змінюють кілька записів одразу (видалення інструктора чи курсанта, створення інструктора з обліковим записом, збереження дня графіка, ТЗ з нагадуваннями), виконуються в транзакції MongoDB (`utils/transaction.js`): або зберігаються всі зміни, або жодна. Потрібен replica set — на MongoDB Atlas він є завжди. На одиночному сервері MongoDB операції працюють без транзакцій, а в лог пишеться попередження.

## Деплой

Підходить будь-який Node-хостинг (Render, Railway, Cloud Run):
- Build: `npm install`
- Start: `npm start`
- Health Check Path: `/health`
- Задайте змінні середовища з таблиці вище, зокрема `PASSWORD_PEPPER`, `CORS_ORIGIN` (домен фронтенду) і `TRUST_PROXY=1`.
